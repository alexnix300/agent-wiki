# Setup prompt v2 (RU)

Self-contained Russian-language setup prompt. Adds `/wrap` + `/handoff`, focus modes, prompt-library, a privacy-gated publications layer and a secrets/ACCESS policy on top of [`setup-prompt.md`](setup-prompt.md). Does not depend on this repo at runtime: paste the block below into Claude Code as is.

````
# Поставь мне личную базу знаний (LLM-wiki) с нуля

Ты будешь вести мою базу знаний: связанные markdown-страницы, которые пишешь и
обновляешь ты, а я читаю в Obsidian и направляю работу. Знание копится от
сессии к сессии. Сделай всё сам, мне только отвечать на вопросы.

## 0. Сначала спроси (одним сообщением, коротко)

1. Для чего база: работа / личное / исследования / всё сразу? Что буду
   отслеживать (проекты, клиенты, люди, цели, темы)?
2. Где лежит папка (по умолчанию `~/Documents/WIKI`)?
3. На каком языке тебе отвечать и писать страницы?
4. Как общаться: тон (прямо / дружелюбно / формально), подробность
   (коротко / средне / подробно), инициатива (делай сам / спрашивай).
5. Какими инструментами пользуюсь (редактор, языки, хостинг, дизайн,
   заметки, менеджер пакетов) и есть ли жёсткие предпочтения.
6. Есть ли общая цель или дедлайн, под который строится вся работа?
7. Какие модули ставить: focus-режимы (помощь с запуском и удержанием
   фокуса), слой публикаций (статьи из базы наружу), git-история.

Ничего не строй до ответов. Категории подбирай под ответы, лишних не создавай.

## 1. Структура папки

```
<VAULT>/
├── CLAUDE.md          # схема и правила (рулбук для тебя)
├── raw/               # мои исходники; ты читаешь, но не меняешь
│   └── assets/
└── wiki/
    ├── index.md       # каталог всех страниц, по разделам, одна строка на страницу
    ├── log.md         # хронология операций, только дописывать
    ├── log-archive.md # сюда уезжают старые записи, когда log.md > ~300 строк
    ├── ACCESS.md      # правила доступа и секретов (см. п. 6)
    ├── NORTH-STAR.md  # только если я назвал общую цель/дедлайн
    ├── me/            # профиль, инструменты, стиль общения, свои скиллы
    ├── projects/  entities/  concepts/  research/  tools/prompts/  analyses/
    └── publications/  # только если выбран модуль публикаций
```

Правила:
- Код, `node_modules`, большие бинарники — никогда внутрь папки (Obsidian
  захлебнётся). Репозитории живут рядом, в базе — только ссылки по пути.
- Формат страницы: YAML-frontmatter (`type`, `created`, `updated`, `tags`),
  заголовок, текст, `[[wikilinks]]` на всё связанное, внизу `## See also`.
- Лог: `## [YYYY-MM-DD] операция | тема` + 1–3 строки.
- Любые схемы (воронки, архитектура, пайплайны) — только ```mermaid,
  никогда ASCII-стрелками. Стрелка внутри фразы («бриф → сценарий») — норм.

## 2. Схема `<VAULT>/CLAUDE.md`

Опиши в ней: структуру, типы страниц, формат, правила index/log, процессы
(ingest, ответ на вопрос, lint), правило «ссылок без страниц не бывает:
либо создай, либо убери», и четыре принципа ведения:

1. **Read Before Edit** — читай страницу целиком перед правкой; перед
   созданием проверь index на похожую.
2. **Minimal Page Surface** — только разделы, под которые уже есть
   содержание. Никаких пустых заготовок.
3. **Surgical Updates** — правь только нужный раздел, структуру не трогай;
   полную переделку — только с моего согласия.
4. **Verify After Edit** — frontmatter валиден, ссылки резолвятся, index
   обновлён, в log дописана строка.

## 3. Глобальная память `~/.claude/CLAUDE.md`

Если файл уже есть — допиши раздел, ничего моего не удаляя. Содержание:

- **Старт любой сессии** (в любой папке): прочитать `wiki/index.md`, последние
  20 записей `wiki/log.md`, `wiki/ACCESS.md`, `wiki/me/agent-personality.md`,
  `NORTH-STAR.md` если есть.
- **По ходу — записывать сам, не спрашивая:** решения и их причины, статусы
  проектов, новых людей/клиентов, находки, личное, чем я поделился. Пропускать:
  разовый дебаг, опечатки, то, что уже есть в git.
- **Конец сессии:** обновить страницы, index, log.
- **Инструменты** (`wiki/me/tools-and-preferences.md`): при первом упоминании
  инструмента — записать; в советах и командах всегда использовать мои.
- **Стиль общения** (`wiki/me/agent-personality.md`: Тон / Подробность /
  Инициатива / Дополнительные правила): любой мой фидбек про общение
  («короче», «без извинений») сразу дописывать туда с датой. Файл важнее
  дефолтов.
- **Профиль** (`wiki/me/user-profile.md`): частые запросы, ритм работы,
  стиль, где я эксперт. Записывать только то, что повторилось 2+ раза,
  обновлять на месте, без психологии.
- **Свои скиллы:** если я 2–3 раза делаю одно и то же — предложи сделать
  `/команду`; после «да» создай в `~/.claude/skills/<name>/SKILL.md` и
  внеси в `wiki/me/custom-skills.md`.
- **Проекты с кодом:** перед работой прочитать страницу проекта в базе; после
  крупного изменения (новый раздел, правило, архитектура) — обновить её в тот же
  ход. В каждом репозитории вести `docs/features/YYYY-MM-DD-slug.md`
  (Что / Зачем / Ключевые файлы / Проверка) — средний слой между коммитами и базой.
- **Авто-память Claude vs база:** авто-память — короткие правила «как со мной
  работать»; база — знания, проекты, решения. Не дублировать.
- Те же четыре принципа ведения — отдельным разделом.

## 4. Скиллы (`~/.claude/skills/<name>/SKILL.md`)

В каждом: frontmatter `name` + `description` (когда срабатывать), шаги,
раздел `## Principles` с четырьмя принципами.

Ядро:
- `/ingest <файл>` — прочитать источник, обсудить со мной 3–5 выводов,
  страница в `sources/`, обновить связанные страницы, index, log.
- `/wiki <вопрос>` — ответ только по базе, с `[[ссылками]]`; ценный ответ
  предложить сохранить в `analyses/`.
- `/wiki-save <инфо>` — положить в правильный раздел.
- `/wiki-status` — счётчики страниц, свежая активность, необработанное в `raw/`.
- `/lint-wiki` — сироты, битые ссылки, устаревшее, противоречия, страницы без
  frontmatter; сначала отчёт, правки после моего ок.
- `prompt-library` (авто) — когда я делюсь удачным промптом, находкой или
  «попробовал X, лучше чем Y» — сохранить в `tools/prompts/` или в
  инструменты, без вопросов.

Сессии:
- `/wrap` (только вручную) — пройти всю сессию: сделано, решения и почему,
  фидбек, открытые хвосты, один следующий шаг → записать в базу → написать
  handoff-файл в `<VAULT>/../handoffs/YYYY-MM-DD-HHMM-slug.md` и путь в
  `handoffs/.pending` → проверить, что всё записалось → только потом
  предложить очистить контекст. Аргумент `keep` — не очищать.
- `/handoff` (только вручную) — открыть файл из `.pending` (или свежий,
  `list` — последние 10), удалить маркер, ответить: где остановились /
  что открыто / один следующий шаг.

Focus-режимы (если выбран модуль): `/focus-start` (запуск: лестница шагов по
5–10 минут, первый ≤60 сек), `/hyperfocus-sprint` (блок 25/50/90 мин с
чекпоинтами), `/dopamine-stack` (переписать список: старт, быстрая победа,
признак готовности), `/cognitive-unload` (выгрузить всё из головы →
кластеры → бросить/делегировать/отложить/сделать), `/anti-distraction`
(правила среды и сценарий возврата), `/urgency-mode` (искусственный
таймбокс, явно помечен как симуляция). Механику — в одну страницу
`concepts/focus-modes.md`, скиллы ссылаются на неё. Триггер — поведение,
а не слова: прыгаю между задачами не закрыв, открыл 3+ треда, кружу вокруг
задачи, раздуваю скоуп. Называй факт («кусок про X остался открытым»), без
ярлыков и диагнозов, без морали, один скилл за ход. Сырая идея без
аудитории/результата/объёма — не исполнять, одним вопросом спросить, чего не хватает.

## 5. Публикации (если выбран модуль)

`wiki/publications/{writing,concepts,research}/` — единственное, что может
уйти наружу. Страница попадает туда только копией и только по моему слову.
`date:` = `created` исходника. Privacy-гейт: ссылка на страницу вне
`publications/` при выгрузке превращается в обычный текст с предупреждением.
Черновик остаётся черновиком, пока я не сказал «публикуй».

## 6. Приватность и секреты — обязательно

`wiki/ACCESS.md` + те же правила в схеме:
- Пароли, API-ключи, токены, номера карт и документов **никогда** не пишутся
  в базу. Только «где лежит»: «ключ X — в 1Password / Keychain / `.env`
  проекта». Если я вставил секрет в чат — не сохраняй его, напомни убрать.
- Чужие личные данные (телефоны, адреса, здоровье) — только с моего явного
  «запиши».
- Страница с `private: true` во frontmatter не цитируется наружу, не идёт в
  публикации и в любые выгрузки.
- `.gitignore`: `.obsidian/workspace*`, `.trash/`, `.DS_Store`, `*.env`,
  `secrets/`. Git — только локально; удалённый репозиторий и любой push —
  только по моей прямой просьбе, и перед push grep на ключи/токены.
- Если делюсь системой с кем-то — делюсь только схемой и скиллами, без `wiki/`.

## 7. Финал

1. Создай всё выше, `git init`, первый коммит.
2. Самопроверка: frontmatter везде валиден, все `[[ссылки]]` резолвятся,
   index перечисляет все страницы, в log запись `setup`, каждый скилл
   виден в списке.
3. Заполни `me/` моими ответами из п. 0.
4. Покажи коротко: что создано (дерево), 5 команд, с которых начать, и как
   открыть папку в Obsidian (Open folder as vault). Предложи сразу сделать
   первый `/ingest` или рассказать о текущих проектах.
````
